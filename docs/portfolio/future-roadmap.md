# 未來規劃

依優先順序分成三個階段。目前方向是先把**平台內部功能**做完善，正式上線所需的外部串接（金流、寄信等）排在之後。

## P0：內部功能補完（目前主線）

- 帳號設定的通知偏好、安全驗證分頁：目前是佔位畫面，尚未實作
- 帳號恢復流程：目前只能停用，無法自助恢復
- 收款管理面板：目前是唯讀檢視，未來可加主動提醒繳費等功能
- 管理員後台：已是獨立的後台 Dashboard（平台概覽數據、系統訊息、申訴裁定三個分頁），待補更多管理維度（歷史記錄查詢、使用者管理等）
- 互評系統：已是完整可用功能，待確認的是評價彈窗的觸發時機是否精準
- 信用分數動態調整：目前是靜態欄位，未來規劃加扣點規則、歷史紀錄與觸發時機

## P1：正式上線所需

- 正式金流串接（目前儲值/付款/代管撥款皆為平台內模擬邏輯）
- 忘記密碼寄信服務
- 服務目錄價格複核（部分服務尚未完成人工複核）
- 正式第三方登入（如 Google OAuth）

## P2：技術債與體驗優化

- WebSocket 取代目前的 polling 機制，降低延遲與請求量
- TypeScript 型別覆蓋
- 自動化測試：已涵蓋群組生命週期（申請→審核→鎖定→啟用→確認→撥款）核心路徑，其餘流程仍主要靠手動測試
- 逾期付款排程通知
- 幾個已知但影響範圍需要進一步評估後才處理的邊界情況與競態條件，持續追蹤中

## 排序原則

優先從 P0 挑選方向；只有明確要準備上線時，才轉向 P1；P2 屬於錦上添花。
