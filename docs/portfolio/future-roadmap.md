# 未來規劃

目前方向是先把**平台內部功能**做完善，正式上線所需的外部串接（金流、寄信等）排在之後。已完成的功能（互評系統、信用分數動態調整等）見 [功能地圖](../product/feature-map.md) 與 [產品總覽](../product/product-overview.md)，不重複列在這裡。

## Now（近期優先）

- 通知偏好、安全驗證：尚未實作，帳號設定畫面目前不顯示這兩個入口
- 帳號恢復流程：目前只能停用，無法自助恢復
- 收款管理面板：目前是唯讀檢視，未來可加主動提醒繳費等功能
- 管理員後台：待補更多管理維度（歷史記錄查詢、使用者管理等）

## Next（中期規劃）

- 正式金流串接（目前儲值/付款/代管撥款皆為平台內模擬邏輯）
- 忘記密碼寄信服務
- 服務目錄價格複核（部分服務尚未完成人工複核）
- 正式第三方登入（如 Google OAuth）

## Later（長期／不確定時程）

- WebSocket 取代目前的 polling 機制，降低延遲與請求量（見 [ADR-0002](../adr/0002-polling-over-websocket.md)）
- TypeScript 型別覆蓋
- 自動化測試涵蓋範圍擴大：CI 已接上（push/PR 自動跑），後端涵蓋群組生命週期主線與解散、成員移除、申訴裁定、續訂、PM 幣儲值、收藏、真實併發衝突等情境，前端涵蓋共用元件、全部 Zustand store、五個核心頁面/彈窗的整合測試；次要頁面（帳號設定、管理員後台）跟瀏覽器端對端測試仍未涵蓋
- 逾期付款排程通知
- 幾個已知但影響範圍需要進一步評估後才處理的邊界情況與競態條件，持續追蹤中

## 排序原則

優先從 Now 挑選方向；只有明確要準備上線時，才轉向 Next；Later 屬於錦上添花。
