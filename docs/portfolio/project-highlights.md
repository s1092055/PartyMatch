# 專案亮點

以下是實作上投入較多心思的幾個部分：

- **交易安全性**：代管扣款、名額檢查、申請狀態轉換都用資料庫層級的條件式更新處理併發（例如「先讀再寫」在雙擊或併發請求下會超額扣款/超收名額，改成「檢查跟寫入合成一個原子操作」解決）
- **事件驅動的全域 Modal**：訊息、通知、儲值這類會被任何頁面觸發的全域彈窗，改用瀏覽器原生事件廣播取代逐層傳遞 props，避免中間元件都要跟著傳狀態
- **多裝置登入 session**：refresh token 存在 Redis、依裝置分開管理，登出或換裝置只影響單一裝置
- **群組狀態機**：核心業務邏輯收斂成一個明確的狀態機（招募 → 額滿 → 待確認 → 啟用 → 服務中 → 續訂／結束），每個轉換都由後端驗證，前端不做本地假設
- **大型元件拆分**：把幾個超過 600 行、混雜版面/邏輯/RWD 分支的元件拆成職責單一的子元件與 hook
- **Polling 而非 WebSocket**：評估過現階段的使用情境（合購媒合聊天室，非低延遲即時系統）後的取捨，不是技術能力限制，詳見 [ADR-0002](../adr/0002-polling-over-websocket.md)
