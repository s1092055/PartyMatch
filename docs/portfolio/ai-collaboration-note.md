# AI 協作說明

給履歷/作品集連結、或面試官問「這個專案用了多少 AI」時用。目的是誠實揭露協作方式，同時講清楚貢獻在哪裡。

## 協作方式

PartyMatch 的產品定位、核心功能規劃、使用者角色設計與整體使用情境由我主導。實作層面大量透過 AI 協作（Claude Code）產出程式碼。

我的工作集中在：

- **產品與功能範圍**：哪些功能要做、優先順序、MVP 邊界在哪
- **架構與設計取捨**：先聽 AI 說明 trade-off，再自己決定要不要做、做到什麼程度，並在用起來覺得不好維護時回頭修正
- **程式碼審查**：跑過多輪 code review 找出併發安全性、重複程式碼、資料一致性等問題並驗證修正
- **手動測試**：依測試計畫實際跑過主要流程

## 為什麼這樣做

對一個學習階段的作品集專案來說，重點不是完全不用 AI 手刻每一行，而是能不能讀懂並解釋 AI 產出的程式碼在做什麼、能不能在它有問題時看出來並要求修正、能不能做「這個功能該不該做」「架構該拆到什麼程度」這類 AI 無法替你決定的判斷。

整理這個專案本身也是在練這些能力：接手既有 codebase、追蹤功能的完整資料流、驗證流程正確性、把複雜的產品邏輯整理成可維護、可對外說明的文件。
