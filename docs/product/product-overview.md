# 產品總覽

## 產品定位

PartyMatch 是共享訂閱媒合平台。使用者在上面探索或建立 Netflix、Spotify、YouTube Premium、Disney+ 等訂閱服務的合購群組，找夥伴、申請審核、付款代管、服務啟用、續訂到糾紛申訴，整個流程都收在同一個平台完成。

## 解決的問題

共享訂閱的媒合現在多半發生在 Facebook 社團、PTT、Discord，靠私訊、Google 表單或人工記帳完成，問題不少：

- 團主與成員互不認識，難以判斷對方可不可信、會不會落跑
- 付款紀錄散落在轉帳截圖與對話紀錄裡，事後對帳困難、容易吵架
- 沒有統一審核機制，任何人都能直接加入，詐騙風險高
- 團主要手動追蹤每個成員的繳費與服務帳號狀態，成員也搞不清楚自己何時該繳下一期

PartyMatch 把媒合、審核、代管撥款、服務帳號確認做成平台內建流程，用 PM 幣（平台內部代管餘額）取代私下轉帳，每一筆金流與狀態雙方都能在平台上查到。

## 主要角色

### 一般使用者（成員）

- 探索與搜尋群組、快速搜尋配對
- 申請加入審核制群組，查看審核結果通知
- 在「我的群組」（成員視角）填寫服務帳號資訊、追蹤訂閱狀態與續訂
- 收藏感興趣的群組
- 透過群組聊天室 / 私人 DM 與團主或其他成員溝通
- 儲值與管理 PM 幣餘額、管理付款方式
- 服務確認期間如有問題可申訴並上傳附件佐證
- 服務確認後可對團主留下評價

### 團主

- 建立群組（選服務 → 選方案 → 群組設定 → 確認送出），可設定最低信用分數門檻篩選申請者
- 審核加入申請，可看到申請者的信用分數與留言
- 在「我的群組」（團主視角）管理成員名單、鎖定群組、啟用服務
- 查看收款管理面板，回報成員服務帳號填寫有誤
- 開始新一期續訂，或結束群組
- 查看自己過往收到的評價

一個使用者可以同時是某群組的團主、也是另一群組的成員，身分不互斥。

### 管理員

- 帳號模型有 `isAdmin` 旗標，具管理員身分者在「帳號設定」頁多一個「管理員」分頁
- 目前唯一支援的管理員操作是**申訴裁定**：對進入 `disputed` 狀態的群組，裁定「團主獲勝（撥款）」或「成員獲勝（退款）」並填寫裁定說明

## 核心流程

1. 探索群組或使用快速搜尋，找到想加入的群組
2. 送出申請（審核制群組等團主審核，免審核制群組直接建立成員資格）
3. 團主審核通過 → 系統自動從申請者 PM 幣餘額扣款進入代管（escrow）
4. 名額額滿後，團主鎖定群組並建立群組聊天室
5. 成員填寫服務帳號資訊，團主確認齊全後啟用服務、代管款項撥給團主
6. 服務啟用後雙方可透過平台管理續訂、查看付款狀態、聊天溝通；對服務內容有爭議可提申訴，由管理員裁定

完整狀態機與各步驟細節見 [使用者流程文件](../flows/user-flows.md)。

## 目前 MVP 範圍

以下功能已在程式碼中實際實作（依 `src/features/` 頁面與 `server/src/routes/` API 核對）：

- **探索與搜尋**：分類篩選、關鍵字搜尋、價格上限、排序（`src/features/explore/`）
- **快速搜尋**：免登入輸入服務、方案、預算，系統推薦符合條件的群組（`src/features/match/`）
- **建立群組**：4 步驟表單（選服務 → 選方案 → 群組設定 → 確認送出），含桌機即時預覽（`src/features/create/`）
- **申請加入**：送出申請、查看審核狀態（`server/src/routes/applications.js`）
- **團主審核**：核准／拒絕申請，核准時自動處理扣款與名額（`src/features/my-groups/host/`）
- **我的群組（雙視角）**：同一頁面依「我是成員」/「我是團主」切換視角，查看訂閱、群組管理、群組紀錄（`src/features/my-groups/`）
- **PM 幣代管與撥款**：申請核准即扣款進入群組代管餘額，啟用服務時撥款給團主（`server/src/routes/tokens.js`、`server/src/routes/groups.js`）
- **續訂**：團主可手動開始新一期續訂週期（`groups.js` 的 `/renew`）
- **申訴與裁定**：成員可在確認期間提出申訴並上傳證據，管理員裁定勝方（`groups.js` 的 `/dispute`、`/adjudicate`）
- **訊息**：群組聊天室、私人 DM、系統通知聊天室，採 5 秒 polling（`src/features/messages/`）
- **通知**：站內通知，含個人通知與系統公告（`server/src/routes/notifications.js`）
- **收藏**：收藏／取消收藏群組（`server/src/routes/favorites.js`）
- **帳號設定**：個人資料、付款方式管理、PM 幣餘額與交易紀錄、帳號停用（軟刪除）（`src/features/account/`）
- **團主評價**：服務確認後成員可評分並留言，可查看團主歷史評價（`server/src/routes/reviews.js`）
- **圖片上傳**：付款憑證、申訴證據附件上傳，經後端代理至 Cloudinary（`server/src/routes/upload.js`）
- **認證**：Email/密碼註冊登入、JWT（accessToken + refreshToken）、忘記密碼（`server/src/routes/auth.js`）

## 不支援的功能

以下項目在目前版本**未實作**，可與 [未來規劃](../portfolio/future-roadmap.md) 對照：

- **正式金流串接**：已安裝 Stripe SDK，但尚未接上真實扣款邏輯；儲值、付款、代管撥款目前皆為平台內模擬邏輯（PM 幣是虛擬餘額，非真實金流）
- **WebSocket 即時通訊**：訊息中心目前以 5 秒 polling 取代即時推播
- **TypeScript**：目前整個專案為 JavaScript，未導入型別覆蓋
- **信用評分完整機制**：`creditScore` 目前是靜態欄位，還沒有依行為動態加減分與歷程紀錄的完整規則
- **逾期付款排程通知**：尚未有背景排程主動偵測逾期並發通知
- **第三方登入**：資料庫已預留 `googleId` 欄位，但目前註冊/登入僅支援 Email/密碼
