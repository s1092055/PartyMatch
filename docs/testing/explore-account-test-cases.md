# 探索頁／快速搜尋／收藏／帳號中心測試案例

涵蓋：探索頁篩選與排序、快速搜尋（`/quick-match`）三步驟與篩選條件、收藏、帳號中心（付款方式、刪除帳號）。對應程式碼：`src/features/explore/`、`src/features/match/`、`src/features/account/`、`server/src/routes/{favorites,paymentMethods}.js`。

測試帳號見 [`test-accounts.md`](./test-accounts.md)。

## 探索頁（`/explore`）

### TC-401：分類篩選與服務篩選連動

**前置條件**：任一帳號登入或未登入皆可（探索頁公開路由）。

**步驟**：
1. 點擊分類 pill（例如「串流影音」）
2. 觀察右側「服務」下拉選單的選項
3. 直接開啟「服務」下拉，不先選分類

**預期結果**：
- 點選分類後，服務下拉只列出該分類底下的服務；點擊已啟用的分類 pill 會取消套用（切回「不限分類」）
- 切換分類會連動把已選的「服務」重設為「不限服務」（`onChange({ category, service: 'all' })`），不會出現「分類」跟「服務」互相矛盾的組合
- 分類維持「不限分類」時，服務下拉的選項依分類分組、附灰色分類標題

---

### TC-402：關鍵字搜尋（debounce 與回填）

**步驟**：
1. 在搜尋框輸入服務或方案名稱關鍵字
2. 在輸入完成前後分別觀察網址列 query string 何時更新
3. 用瀏覽器上一頁/下一頁切換

**預期結果**：
- 輸入後有 300ms debounce 才會觸發 `onChange`／更新 URL，不會每個按鍵都觸發
- 尾隨空白（正在輸入時）不會被提前 trim 打斷輸入
- 瀏覽器上一頁/下一頁改變 URL 的 `q` 參數時，輸入框內容會同步回填

---

### TC-403：價格篩選（預設區間與自訂金額）

**步驟**：
1. 依序選擇「100 以下」「200 以下」「300 以下」「500 以下」
2. 選擇「自訂金額」，輸入框出現，測試以下輸入：空白、`0`、負數、非數字字元、正常正整數
3. 輸入合法金額後按 Enter，另建一次輸入合法金額後改為失焦（blur）觸發

**預期結果**：
- 4 個預設金額選項可直接篩選，`maxPrice` 更新為對應字串
- 自訂金額輸入 `0`、負數、非數字時，**保留在編輯狀態**讓使用者修正，不會靜默送出或關閉輸入框
- 輸入合法正整數後，Enter 與失焦都能送出並套用（`maxPrice` 更新為該數字字串），下拉選單文字顯示「`{金額}` 以下（自訂）」
- 切換前後搜尋框跟三個篩選框的寬度應保持一致（見 [`rwd-test-cases.md`](./rwd-test-cases.md) TC-305）

### TC-404：排序切換

**前置條件**：至少存在多筆 `recruiting` 狀態的群組（seed 資料已足夠）。

**步驟**：
1. 依序切換「推薦排序」「團主評分最高」「價格由低到高」「剩餘名額最少」

**預期結果**：
- 每個排序選項套用後，結果列表順序應符合對應規則（可肉眼核對前幾筆的評分/價格/剩餘名額是否遞增或遞減正確）
- 排序條件變更不影響已套用的分類/服務/價格/關鍵字篩選

### TC-405：無符合結果的空狀態

**預期結果**：

### TC-411：每人費用區間滑桿（雙把手夾住、輸入框同步）

**步驟**：
1. 進入步驟二篩選區塊，拖曳左側把手（最低金額）超過右側把手（最高金額）的位置
2. 拖曳右側把手（最高金額）低於左側把手（最低金額）的位置
3. 在下方「最低金額」輸入框直接輸入一個大於目前最高金額的數字
4. 在「最高上限」輸入框輸入一個小於目前最低金額的數字
5. 在「最高上限」輸入框清空後失焦
6. 勾選「不限」，再取消勾選

**預期結果**：
- 步驟 1／2：兩個把手互相夾住不會交叉，最低不會拖過最高、最高不會拖過最低
- 步驟 3：最低金額被夾回目前的最高金額（不會把最高金額往上推）
- 步驟 4：滑桿刻度上限（`priceMax`）跟著新的最高金額同步下修，若因此小於目前最低金額，最低金額也會被連動下修，滑桿把手不會因為 value 超出自己的 max 屬性而消失
- 步驟 5：輸入框清空立即補回預設上限，不會停留空白
- 上方顯示的金額文字（`PriceRangeAmount`）跟輸入框、滑桿把手位置三者任何時候都應該一致，不會看到互相矛盾的數字（對應近期修正的「輸入框跟實際選取值脫節」bug，見 [`bug-log.md`](./bug-log.md)）
- 勾選「不限」後滑桿與輸入框停用（disabled），但仍記得勾選前的區間；取消勾選後應還原成取消前選的區間，不會重置回預設值

### TC-412：團主信用分數門檻按鈕與滑桿連動

**步驟**：
1. 分別點擊「不限」「60+」「70+」「80+」「90+」按鈕
2. 改為直接拖曳滑桿到例如 65 分

**預期結果**：
- 點擊門檻按鈕時滑桿與按鈕高亮同步
- 拖曳滑桿到兩個門檻中間值（例如 65）時，會亮起「不大於目前值的最大門檻」按鈕（60+），而不是完全不亮或亮錯
- 滑桿拖到 0 或低於 60 時，只有真的點擊「不限」才會亮「不限」按鈕，不會因為滑桿數值低就自動誤判成「不限」

### TC-413：搜尋結果與名次徽章

**前置條件**：設定的篩選條件能配對到 3 個以上 `recruiting` 且有剩餘名額的群組（seed 資料的 G1/G2/G12/G17 皆為 `recruiting`，可用寬鬆條件配對到多筆）。

**步驟**：
1. 完成步驟一、二後點擊「開始搜尋」

**預期結果**：
- 只回傳狀態為招募中且還有名額的群組，`full`／其他非招募中狀態不會出現
- 已額滿或非招募中的群組（例如 G3 full）不應出現在結果中
- 前 3 名依推薦分數帶金/銀/銅徽章，徽章隨卡片一起 hover 縮放（不脫落、不維持原地）
- 未登入時搜尋照常運作，只是不會排除「自己開的團」（因為沒有登入者可比對）

## 收藏

### TC-420：加入與移除收藏（toggle 冪等）

**前置條件**：demo1 登入，找一個尚未收藏的群組（例如 G12 Canva）。

**步驟**：
1. 點擊收藏愛心圖示
2. 重新整理頁面，確認收藏狀態持續
3. 再次點擊收藏圖示取消收藏

**預期結果**（`POST /favorites/:groupId`，toggle 語意）：
- 首次點擊：`201`，`favorited: true`，愛心圖示變為已收藏樣式（`FavoriteToggleButton`，紅色填滿）
- 重新整理後收藏狀態應正確從 `GET /favorites` 讀回，不會因為只存在前端 state 而重整後消失
- 再次點擊：`200`，`favorited: false`，愛心圖示恢復未收藏樣式
- 同一個 `FavoriteToggleButton` 元件同時用在探索頁卡片、群組詳情 Modal、快速搜尋結果卡片三處，三處的收藏狀態應保持一致（收藏其中一處，其他處重新開啟也要顯示已收藏）

## 帳號中心

### TC-430：新增付款方式（上限 2 筆）

**前置條件**：demo3（尚無付款方式）登入帳號中心「付款方式」分頁。

**步驟**：
1. 新增第一張卡（填卡號、到期日 MM/YY、CVC、持卡人姓名）
2. 新增第二張卡
3. 嘗試新增第三張卡

**預期結果**（`POST /api/payment-methods`）：
- 卡號與到期日為必填，兩者皆填才能送出（CVC、持卡人姓名前端未強制必填，僅存本地不會送到後端 schema 外的欄位）
- 第一筆新增後自動設為預設（`isDefault: true`）
- 第二筆新增成功後，畫面上限制新增入口消失（`cards.length < 2` 才顯示「新增付款方式」按鈕）
- 後端也有相同上限保護：直接呼叫 API 新增第 3 筆應回傳 400「最多只能儲存 2 種付款方式」

---

### TC-431：切換預設付款方式與刪除後預設遞補

**前置條件**：延續 TC-430，demo3 已有 2 張卡，第一張為預設。

**步驟**：
1. 點擊第二張卡的「設為預設」
2. 刪除目前的預設卡（第二張）

**預期結果**：
- 設為預設後，畫面上該卡片顯示「預設」badge，且排到清單最前面；後端同步（`PATCH /api/payment-methods/:id/default`，transaction 內先清空其他卡的 `isDefault` 再設定新的）
- 刪除目前預設卡後，剩下唯一一張卡應自動被設為新的預設（前端與後端各自都有遞補邏輯，`DELETE /api/payment-methods/:id` 後端會查詢剩餘卡片中 `createdAt` 最早的一筆設為預設）
- 刪除後只剩 1 張卡時，「新增付款方式」入口應重新出現

### TC-432：刪除帳號（軟停用，需輸入密碼）

**前置條件**：另建一個測試帳號（避免動到 demo 帳號，可用 `/register` 新建一個一次性帳號），登入後前往帳號中心「其他設定」分頁。

**步驟**：
1. 點擊「刪除帳號」
2. 不輸入密碼直接點擊「確認刪除」
3. 輸入錯誤密碼送出
4. 輸入正確密碼送出

**預期結果**：
- 步驟 2：「確認刪除」按鈕在密碼欄為空時應為 disabled，無法送出
- 步驟 3：後端驗證密碼錯誤時回傳失敗，畫面顯示紅字錯誤訊息（`deleteError`），不會關閉確認區塊
- 步驟 4：成功後 toast 顯示「帳號已停用，如需恢復請聯絡客服」，導向首頁；該帳號應無法再登入（`deactivatedAt` 已寫入），且資料不會被實際刪除（軟停用，非硬刪除）
- 點擊「取消」應關閉確認區塊並清空已輸入的密碼與錯誤訊息

### TC-436：目前狀態（線上狀態點）顯示與手動切換（需 2 個帳號）

**前置條件**：同 TC-435，demo1、demo3 互為同一群組成員。

**步驟**：
1. demo1 登入帳號中心「其他設定」→「一般偏好」→「目前狀態」，依序切換「在線中」「忙碌中」「已離線」
2. 每次切換後，demo3 查看群組成員名單／聊天室成員面板／DM 對話列表裡 demo1 頭像旁的狀態點
3. demo1 檢查自己 Hero 卡片頭像右下角的狀態點是否同步

**預期結果**：
- 狀態為手動選擇，不是自動偵測登入/離線，choice 不會因為 demo1 關閉分頁或登出而自動改變
- 三種狀態對應顏色：在線中＝綠、忙碌中＝橘（amber）、已離線＝紅，圖示皆為帶白色外框的小圓點
- demo3 側能即時（或下一次重新整理／輪詢後）看到 demo1 狀態點顏色跟著切換
- demo1 自己 Hero 卡片頭像上的狀態點也會同步更新
