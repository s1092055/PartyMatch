# 條件搜尋

## 使用者目標
在探索群組頁想更精準地找到符合需求的群組時，透過「選擇服務 → 設定方案與篩選條件 → 查看搜尋結果」三個步驟，篩出符合條件、依推薦分數排序的群組，不用登入也能用。

## 流程
```mermaid
flowchart LR
  A[探索群組頁點擊條件搜尋] --> B[選擇服務類別]
  B --> C[設定方案與篩選條件]
  C --> D[套用篩選]
  D --> E[依推薦分數排序]
  E --> F[顯示結果，前幾名加名次徽章]
  F --> G[點擊卡片開啟群組詳情]
```

1. **開啟入口**：在探索群組頁點擊「條件搜尋」按鈕開啟
2. **選擇服務**：可複選有興趣的服務類別，至少選一個才能繼續
3. **設定方案與篩選條件**：針對每個已選服務指定方案（或不限），設定關鍵字、每人費用區間、團主評分下限、群組成立時間等條件
4. **開始搜尋**：對已快取的群組資料套用篩選，通過篩選的群組再依推薦分數（團主評分、剩餘名額、扣款週期、價格優勢等綜合考量）排序
5. **查看結果**：結果依分數排序，前幾名加上名次徽章；點擊卡片開啟群組詳情，後續申請流程見 [申請加入流程](./apply-join-flow.md)
6. 可以隨時調整條件重新搜尋，或整個重來
7. 搜尋結果只顯示在這個功能自己的畫面裡，不會影響探索群組頁本身原有的群組列表

## 產品決策
- **收斂成探索群組頁內的專屬工具**：不再是全站隨處可觸發的入口，只在使用者已經在探索群組、想進一步縮小範圍時才需要用到
- **跟探索群組頁的預設列表完全脫鉤**：探索群組頁本身的群組列表維持「依上架時間新到舊」的原始瀏覽體驗，不會被這裡的搜尋條件影響
- **免登入也能使用**：讓還沒註冊的使用者也能先體驗篩選結果，只有真的要申請加入時才要求登入
- **篩選條件與結果只存在當下這次操作**：關閉就清空，不會被記錄或帶到別處，避免使用者的搜尋偏好被意外保留
- **推薦分數是前端即時計算**，不是後端排序結果，也不會存進資料庫

## 驗證重點
- 搜尋結果只會回傳招募中且有名額的群組
- 沒有符合結果時顯示空狀態並引導去看探索頁完整列表，不當成錯誤處理
- 運算基於頁面載入當下的快照資料，可能跟資料庫當下的實際狀態有些微落差
