# 命名慣例

整體原則：檔名與資料夾結構直接反映程式碼的職責與層級，可從檔名直接判斷內容所屬層級。

## 大致慣例

- **資料夾**：依「產品功能」（`features/`）與「技術層次」（`common/`：api、stores、utils、layout）分層；全站共用 UI 元件統一收斂在單一資料夾內，再依用途細分
- **元件**：依角色加上固定字尾——路由頁面元件以 `Page` 結尾、Modal 以 `Modal` 結尾、列表項目卡片以 `Card` 結尾；元件檔名一律 PascalCase 且與匯出名稱一致
- **Hooks**：一律以 `use` 開頭，依使用範圍放在共用工具或各 feature 自己的 hooks 資料夾
- **Store（Zustand）**：一律 `useXxxStore`，對應其主要管理的後端資源
- **API 模組**：一律 `xxxApi.js`，對應複數資源名；函式命名依語意選用貼切動詞（讀取/新增/更新/刪除），不強制單一前綴
- **後端 Route／Prisma Model**：Route 檔名對應複數資源名，Model 命名採單數 PascalCase，對應資料表名則轉換為 snake_case 複數

少數例外（如底層元件對齊第三方套件慣例命名、路由數量過多而拆子資料夾）皆有明確理由，非隨意不一致。
