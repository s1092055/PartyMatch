# API 總覽

後端提供一組 REST API，依資源分類（使用者、群組、申請、成員、訂閱、通知、對話、收藏、評價、服務目錄、PM幣、檔案上傳、系統訊息、帳號留言、管理員後台），遵循標準資源導向命名慣例（GET/POST/PATCH/DELETE 對應查詢/建立/更新/刪除）。

## 認證層級

端點依需求分四種：**公開**（如服務目錄查詢）、**選擇性登入**（訪客可呼叫，登入後看到更多資料，如探索頁群組列表）、**需登入**、**需管理員**（如申訴裁定、系統公告發送）。

## 設計原則

- 群組相關端點另外處理狀態機推進動作（啟用、確認、申訴、解散、續訂等），與一般 CRUD 分開
- 涉及金流的操作（申請、退款、撥款）在後端以交易方式保證原子性，前端不直接操作餘額
- 回傳「其他使用者」資料的端點會依對方的隱私設定遮罩敏感欄位

認證 token 機制見 [認證機制](./authentication.md)。
