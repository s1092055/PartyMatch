# Architecture / Product 演變記錄

只記真正值得一提的決策轉折，首頁 RWD/動畫細節經過非常多輪微調，過程從略。

- **服務帳號欄位改成動態表單**：針對平台內 28 種訂閱服務逐一調查真實的帳號共享機制（email 邀請／地址／邀請碼／共用帳密等），把「填寫服務帳號」表單從不分服務一律只收 email，改成依服務動態顯示對應欄位
- **通知建立方式收斂到後端**：從「前端呼叫成功後另外補送」改成「後端在同一個請求內直接建立」，避免使用者提早關閉分頁導致通知遺失；同時移除了一個可以自由指定通知內容的通用端點，避免被用來偽造通知
- **管理員後台獨立成專屬 Dashboard**：從帳號中心裡的一個分頁，拆成獨立頁面並補上平台概覽數據
- **修過一個狀態轉換與退款邏輯耦合的 bug**：兩件事原本共用同一個條件判斷，特定情境下會讓狀態轉換被誤判成不用處理而卡住，已拆成兩個獨立步驟
- **iPad 導覽改版**：發現觸控裝置沒有 hover、原本沿用手機版導覽會卡在收合狀態，改成獨立的 `TabletSidebarDrawer`，跟桌機側邊欄共用同一份導覽設定
- **按鈕互動統一**：點擊回饋從「點擊縮小」改成「hover 上浮」，套用到所有動作按鈕
