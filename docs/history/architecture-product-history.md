# Architecture / Product 演變記錄

- 首頁每個區塊的自動縮放機制原本只避開底部的浮動導覽列，沒有一併避開頂部的浮動導覽列，垂直置中的內容偶爾會蓋到其中一邊；改成兩邊都納入計算，並修正了縮放比例共用邏輯裡一個會讓畫面瞬間跳動的異常值判斷問題
- 未完成功能的視覺表現原本不一致（有的直接停用並標示「即將推出」，有的可以送出後才跳錯誤訊息），先統一成同一套「停用 + 即將推出」的視覺語言，並清掉幾個因此變成死程式碼的舊功能；後來又進一步改成直接把入口整個從畫面上拿掉，而不是留一個按下去沒反應的按鈕
- 主導覽的裝置類型切換點原本跟一般版面排版共用同一個斷點，實際用 iPad 測試後發現觸控裝置沒有 hover、側邊欄卡在收合狀態，改成裝置類型切換用獨立、更大的斷點；同一批也把版面高度計算改用對行動瀏覽器更準確的視窗高度單位
- 按鈕的點擊回饋從「點擊縮小」統一改成「hover 上浮」，套用到所有動作按鈕（小型純圖示工具鈕維持原樣，避免密集排列時一起跳動）
- 修過一個申請狀態轉換跟退款邏輯耦合在一起的 bug：兩件事原本共用同一個條件判斷，特定情境下會讓狀態轉換被誤判成不用處理而卡住，已拆成兩個獨立步驟
- 信用分數查看入口從側邊欄搬到帳號中心
- 針對平台內 28 種訂閱服務做過一次逐一調查，確認每個服務真實的帳號共享機制（email 邀請／地址／邀請碼／共用帳密等），並依調查結果把「填寫服務帳號」表單改成依服務動態顯示對應欄位，取代原本不分服務、一律只收 email 的寫法
- 業務通知的建立方式從「前端呼叫成功後另外補送」改成「後端在同一個請求內直接建立」，避免使用者提早關閉分頁導致通知遺失；同時移除了一個可以自由指定通知內容的通用端點，避免被用來偽造通知
- 管理員後台從帳號中心裡的其中一個分頁，獨立成專屬的 Dashboard 頁面，並補上平台概覽數據與系統訊息功能
- 首頁手機版捲動吸附原本全站統一用 mandatory（滑一點就整段吸到下一區），Hero 區塊內容較短、輕滑一下就會被吸走的體感太明顯，改成只在 Hero 還占視窗一半以上時暫時放寬成 proximity，離開 Hero 後其餘區塊維持原本的 mandatory；同時「適合每一種共享生活」的圖片網格跟「我想成為？」的影片卡片，手機版兩側原本留白偏多，改成貼近全寬顯示（留一點點側邊間距，不完全貼齊螢幕邊緣）
- 首頁 Hero 動態切換 snap 類型的機制上線後，發現手機版「回到頂部」按鈕的平滑捲動偶爾會在途中被彈回去、回不到真正頂部——捲動到一半剛好跨過 Hero 的切換門檻，snap 類型被換掉打斷了進行中的動畫；修成觸發捲動前先暫時拿掉 snap 相關 class，等捲動真的停下來才還原
- 「我想成為？」的影片容器手機版改成直式 9:16（之後要放手機操作畫面錄影，直式比較貼近實際內容），桌機／平板維持原本橫式 16:9
- 首頁每個 Section 的自動縮放機制原本共用同一個全域縮放比例，發現調整其中一個 Section 的內容會連帶影響到其他 Section 的縮放，改回讓每個 Section 各自獨立計算，不再跨 Section 共用
- 「我想成為？」手機版版面微調：階段頁籤列從影片正上方改成貼在影片左側排成直式選單（配合影片改直式後多出來的橫幅空間）；子流程 Select 從影片左下角移到左上角並改全寬；團主／成員切換按鈕從標題下方另起一排，改成縮小尺寸貼著標題放同一排、整組置中
- 「我想成為？」手機版子流程選單再改一版：拿掉直式側邊欄位，改成點擊影片頂端全寬按鈕才叫出底部 Drawer，階段頁籤跟子流程都收進同一個 Drawer 裡切換，影片容器可以整個滿版；同時移除影片下方的子流程說明文字（桌機/平板維持原本頁籤貼頂＋影片右側 hover 展開選單不受影響）
